# GraphQL Regression Suite

Golden-snapshot regression tests for the full `GraphQLQueries.js` surface. Queries are
built by the **real frontend module** (`frontend/webapp/src/models/GraphQLQueries.js` via
`prepareQueries`), POSTed to `{target}/{en|ko}` exactly like `BoMOnlineAPI.js` does, and
compared against committed baselines. This is the safety net for the resolver overhaul:
the refactored backend must produce identical responses.

Spec: `docs/specs/2026-06-09-graphql-regression-test-suite.md` ·
Plan: `docs/plans/2026-06-09-graphql-regression-test-suite.md`

## Setup (once)

```bash
cp tests/.env.test.example tests/.env.test    # fill in; NEVER commit (public repo)
```

Constraint discovered during capture: the backend's `signup` resolver
(`cleanUsername` in `src/resolvers/BomUser.ts`) **forces the stored username to the
email's prefix** when an email is supplied — `TEST_USERNAME` must equal the part of
`TEST_EMAIL` before the `@`, or signin will never match the user that signup created.

## Daily use

| Command | What it does |
|---|---|
| `TARGET=prod npm run test:gql` | verify prod against baselines (green + 24 prodStale skips) |
| `TARGET=local npm run test:gql` | verify a local backend (`npm run dev:backend`) — the refactor gate |
| `TARGET=dev npm run test:gql` | verify dev (green since the 2026-06-09 proxy fix) |
| `npm run test:gql:capture` | (re)capture baselines from prod; existing files skipped |
| `RECAPTURE=1 npm run test:gql:capture` | force-overwrite baselines — only after intentional contract changes |
| `npm run test:gql:harvest` | regenerate the input matrix from prod (then recapture) |

Scope a run: `TARGET=prod npx jest --config tests/jest.config.js -t "person."`

## How it works

- **Matrix** (`tests/matrix/inputs.json`, committed, generated by `harvest.mjs`): per
  query type → volatility `tier`, `auth`/`langs`/`prodStale`/`sandboxSkip` flags, named
  input cases (single / batch / missing / permutations).
- **Tiers:** `exact` (byte-for-byte) · `scrubbed` (volatile keys masked, then exact) ·
  `shape` (structure/types only, null = wildcard). On sandbox targets (dev/local),
  auth'd queries auto-downgrade to shape — sandbox mode swallows user writes.
- **Language priming:** the backend leaks a process-global scripture-guide language
  across requests (`docs/bugs/2026-06-09-scripture-guide-global-lang-leak.md`), so the
  runner posts a trivial scripture query in the case's language before every case.
  Baselines are therefore steady-state per-language and stay valid after the bug is fixed.
- **Errors are contract:** GraphQL error responses are baselined, reduced to sorted
  deduplicated messages (stacktraces leak server paths; racing crashes make full error
  objects nondeterministic).
- **prodStale types** (`object`, `objectList`, `passagenotes*`, `history`): the deployed
  prod schema predates them, so they capture from the local backend (current code, same
  `bom_prd` DB) and skip visibly on `TARGET=prod`.
- **sandboxSkip types** (`uploadProfileImage`, `signup`): structurally mangled on sandbox
  targets; verified against prod only.
- Mutations run against the dedicated test user only, idempotently (same values each
  run), ordered: mutations → reads → `signout` last. Capture only runs against prod
  (plus local for prodStale) and is deterministic — proven by double-capture tree-hash.

## Bugs surfaced by this suite (all fixed 2026-06-09, write-ups in docs/bugs/)

- **dev `/ko` served English** — setupProxy mount-path strip; fixed, dev fully green.
- **scripture-guide global language leak** — fixed in repo (lang per call); prod still
  runs the leaky build until the next deploy, so the runner's language primer stays.
  **Until that deploy, `TARGET=prod` `[en]` cases with generated references (person,
  places, chiasm…) can flake when live Korean traffic races the primer** — rerun, or
  trust `TARGET=local`/`TARGET=dev`, which are deterministic-green on fixed code.
- **object.index resolver crash** — fixed (missing include + null-safe slug); object
  baselines recaptured with clean data.
- **frontend `shortLink` field mismatch** — fixed (selects `hash`/`string`); baselines
  recaptured with real data.

## After the overhaul changes behavior intentionally

Recapture just the affected types and commit the diff — it documents the contract change
(for `prodStale` types the local backend must be running — their capture pulls from
`localhost:5005`):

```bash
RECAPTURE=1 CAPTURE=1 TARGET=prod npx jest --config tests/jest.config.js -t "<type>."
```
