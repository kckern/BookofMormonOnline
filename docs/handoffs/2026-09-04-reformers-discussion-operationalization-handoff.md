## 2. What's live (the pipeline)

1. **Passage pick** (`passagePicker.ts`) — random BoM `bom_text` unit, weighted **85% discourse+poetry / 15% narrative** (`BUCKET_WEIGHTS`). Discourse and poetry share one bucket so scarce poetry (~1% of the corpus, 42 units) isn't oversampled. Expands to a 4–12 verse passage.
2. **Opener** (`runManagedDiscussion`) — chosen bot argues the passage (~110–170 words), emits a `HIGHLIGHT:` phrase validated against the linked block → attached as a `role:highlight` span (yellow `<mark>`). Anchor = page slug; a scripture-excerpt **card** always renders. No redundant reference header.
3. **Follow-ups** (`processDueTurns`) — each turn gets a discourse **move** (expand/clarify/pushback/probe/reframe/concede_qualify), ~50% friction, character-gated, never "I agree". Concise (length histogram, mean ~2.4 sentences). ~1/3 attach their own BoM scripture card. After the first clarify/pushback, the **opener re-enters** (move `respond`).
4. **Generation** (`generate.ts`) — Mastra agent per bot, `gpt-5.6-luna`, `reasoningEffort` (default `high`). Fully logged.

## 5. How to operate

- **Pause posting:** `UPDATE bom_bot_schedule SET enabled=0 WHERE channel_url='981706…'` (+ optionally `UPDATE bom_ai_discussion_turn … SET status='skipped'` for pending follow-ups). Re-enable with `enabled=1`.
- **Fire one thread now (review):** run `scripts/run-once-discussion.mts` (uses local code + the dev OpenAI key, posts to the live channel). It posts the opener + queues staggered follow-ups; the prod scheduler fires the follow-ups (accelerate by setting their `due_at=UTC_TIMESTAMP()`).
- **Validate changes safely (no posting):** run `scripts/dryrun-discussion-quality.mts`.
- **Tune:** edit the code constant / DB config above, then deploy (push `dev`→`prod` triggers blue-green).
- **DB access:** dev backend env creds (`bom_app@bom_prd`) at `/run/user/1003/bom-dev.env`; use `timezone:'Z'` on ad-hoc mysql2 connections (see Gotchas).

## 9. Gotchas

- **DB timezone skew:** the app pool uses `timezone: 'Z'` (UTC). Ad-hoc mysql2 connections default to `'local'`, and this host is `America/Los_Angeles` (PDT, UTC-7) — so reads of `NOW()`/DATETIME columns come back **+7h skewed** unless you set `timezone: 'Z'`. Bit me on `next_run_at` verification.
- **No secrets to stdout:** never echo `OPENAI_API_KEY` / DB creds / SSH keys. Pipe fetch→consume in one chain.
- **Enabling mid-thread with past-due turns** makes the first tick generate several luna-high replies at once → CPU spike on the 2-vCPU/no-swap prod box → transient container `unhealthy` (recovers, no crash, site stays up). Normal staggered cadence avoids it.
- **`bom_ai_discussion_config.enabled` vs `bom_bot_schedule.enabled`:** disabling the *schedule* row stops new threads but `processDueTurns` still fires pending follow-ups (it gates on `config.enabled` + `thread.status='active'`). To fully pause, skip pending turns too.
- **Prod deploys** need explicit sign-off each time (the auto-mode classifier blocks otherwise). Prod root disk runs ~88-99% full; the blue-green script prunes before pull, but watch for "no space left".
