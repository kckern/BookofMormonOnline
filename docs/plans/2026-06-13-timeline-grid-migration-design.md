# Timeline: Leaflet → Scrollable Grid Migration

**Date:** 2026-06-13
**Status:** Design approved; implementation starting with the reconciliation script.

## Goal

Replace the current Leaflet-based `frontend/webapp/src/views/Timeline/` (an image-tile
pan/zoom map with markers) with a **pure HTML/CSS/React scrollable 2D grid**. Rows = time,
columns = place/lineage. Each Book of Mormon event becomes a positioned card. No Leaflet, no
tile pyramid, no zoom.

The redesign was prototyped as a spreadsheet export at
`~/Downloads/Timeline Grid/Sheet1.html` (with `labels.json`, a copy of the GraphQL
`timeline` payload).

## Scope (v1)

- **BoM events only.** Named events, `📍` place labels, and `💥` battle markers.
- **Out of scope for v1:** the world-history context track (Egypt/Assyria/Babylon/Persia/
  Greece columns in `Sheet1.html`, and `Sheet2.html`). It has no `labels.json` backing and
  would need its own data source.

## Key findings from the prototype

- `Sheet1.html` is a Google-Sheets export: 1 table, 40 data columns × ~130 `tr` rows
  (content rows interleaved with `◜◝◟◞` box-corner connector rows).
- **No machine keys.** Cells carry only visible text — no hyperlinks, slugs, or data
  attributes. Mapping a cell to a `labels.json` entry must go through text.
- **Text match is ~60% clean.** Of 188 named cells, ~111 strong-match by normalized text;
  the rest include false positives (`Jared` → *The Jaredite Promised Land* via substring)
  and gaps both directions (`Shiz`, `Lehi and Sariah` have no clean heading; some headings
  have no cell). **Requires a human-in-the-loop reconciliation pass.**
- **x/y is NOT a reliable driver.** Measured correlation between sheet position and
  `labels.json` coords is near zero (`corr(col,x)=0.018`, `corr(row,y)=0.153`). The sheet is
  a hand-authored re-layout: lineages run as **bands with continuation arrows** (`Nephites ▷`,
  `◃ Colonial Expedition`), so one slug appears in **multiple** cells, and places re-stamp per
  era. x/y is useful only as a **local tiebreaker** to reject false matches, not as a
  transform source.

## Architecture (TILE model — supersedes the earlier sparse "placement map")

The sheet is a **tilemap**: every cell is a tile. Reverse-engineering the visual
(rendered via headless Chrome screenshot) showed the design is three layers:

1. **Fill tiles** — lineage bands are solid color fills (3,000+ blank colored cells).
   Colors map to lineages: teal `#134f5c` Jaredites, purple `#351c75` early Lehi,
   maroon `#85200c` Nephites, green `#38761d` Lamanites, gold `#bf9000` Mulekites/Zarahemla,
   blue `#1c4587` Zeniff's colony, orange `#b45f06` Alma's people, cream `#fff2cc` post-Christ.
2. **Rounded corners** — the `◜◝◟◞` glyph cells (and combined caps: `◗ = ◝+◞`, `◣ = bl`)
   carry the band color AND mark which corner of that tile gets `border-radius`. They are
   NOT noise and NOT separate boxes — they are per-tile corner-rounding instructions.
3. **Anchored labels/icons** — event labels, `📍` places, `💥` battles are anchored to a
   tile but **overflow it** (`overflow: visible`, not clipped). White "duration bars" are
   simply the light page background showing through gaps in the colored bands.

### Grid data — hardcoded in React (`gridTiles.json`)
```
{ cols, rows, tiles: [ { r, c, w, h, k:'fill'|'event'|'place'|'battle',
                         bg?, fg?, rd?:['tl','tr','bl','br'], t?:label, slug? } ] }
```
Generated by `scripts/timeline-grid/build_tiles.py`.

### Labels — GraphQL, unchanged
Keep `BoMOnlineAPI({ timeline: true })`. Each returned entry
(`slug, heading, date, html, text.slug, file`) is **joined by `slug`** to the hardcoded
placement.
- Entry with no placement → skipped.
- Placement with no matching label → placeholder cell (flagged in the reconciliation report).

### Schema evolves later
Once placements are trusted, migrate `{row,col,rowSpan,colSpan}` into `BomTimeline` + the
`Event` GraphQL type and retire `x/y/w/h/z/o`. The component then reads grid coords from GQL
and the hardcoded map is removed.

## Data pipeline (one-time reconciliation script)

1. Parse `Sheet1.html` → for every BoM cell:
   `{ text, row, col, colSpan, rowSpan, colorClass, kind }`, dropping the world-history
   columns and the `◜◝◟◞` connector glyphs.
2. Join each cell to a `labels.json` entry:
   - (a) normalized text match on `heading` + `slug`,
   - (b) break ties / reject false positives using x/y proximity,
   - (c) collapse band-repeats so one slug keeps its full `{row,col,rowSpan,colSpan}`
     footprint.
3. Emit:
   - **placement map** (`slug → {...}`) for the React component,
   - **reconciliation report**: confident matches, ambiguous (needs human), unmatched cells,
     unmatched entries.
4. Hand-fix the ambiguous handful; commit the placement map. `x/y/w/h/z` stay as fallback.

## React rendering (tile model)

- `Timeline.js` drops `leaflet`, `ReactDOMServer`, the tile layer, zoom handlers,
  `showZoomlevel`. Keeps `useRouteMatch` deep-link, the `label()` title effect, scripture
  links, `assetUrl` art.
- Light-background scroll container wrapping one CSS Grid
  (`grid-template-columns: repeat(cols, var(--col-w)); gap: 0`).
- **Two passes** so labels paint above bands: render `fill` tiles first (band colors +
  per-corner `border-radius` from `rd`), then `event`/`place`/`battle` tiles as
  `.tg-anchor` (`overflow: visible`, `white-space: nowrap`) so labels overflow their tile.
- Event tiles join GraphQL labels by `slug`; clicking opens the **info-box modal** (heading,
  date, art, `html`, scripture link) — replaces the Leaflet popup and `renderToString`.
- Text color derives black/white **contrast** from each tile's `bg` (sheet `fg` is
  unreliable). White bars = page background through band gaps.
- **Deep-link**: `/timeline/:slug` scrolls the tile into view + highlights it; clicking does
  `history.push('/timeline/{slug}')`.
- **Zoom**: removed. Optional `--col-w`/`--row-h` size control later; not v1.

Verified visually by generating a static preview from `gridTiles.json` and screenshotting it
(headless Chrome) against the original `Sheet1.html` render — bands, corners, white bars,
labels, and markers match.

## Backend grid cutover sequence (why the API grid is staged, not live)

The backend now exposes `Event.grid` and a `bom_timeline` grid migration exists,
but **nothing consumes it yet** — by design. The frontend still reads event
placement from the static `gridTiles.json`, and its GraphQL call deliberately
does NOT request `grid`. Wiring it prematurely would break production: the CRA
app proxies to prod (`bookofmormon.online`), which runs the old schema — querying
an unknown `grid` field would error and blank the timeline.

Correct activation order (each step gated on the previous):
1. **Deploy** the backend with `Event.grid` to prod. (`grid` resolves to `null`
   safely — `selectAll()` omits the not-yet-existent columns.)
2. **Apply** the private workspace's `sql/migrations/2026-06-13_bom_timeline_grid.sql`
   (one-shot; down-migration included) and run `npm run codegen:db` to regenerate
   `codegen/db.d.ts` for real (then the optional `grid_*` in `TimelineRow` can
   become required-nullable).
3. **Wire** the frontend: add `grid { row col rowSpan colSpan kind bg }` to the
   timeline query and render event placement from the API, keeping only the band
   fills / date-axis chrome in `gridTiles.json`.
4. **Retire** `x/y/w/h/z/o` and the static event coordinates.

Until step 3, the API grid + DB columns are intentionally dormant. `placements.json`
keeps the static and DB representations from drifting in the meantime.

## Implementation order

1. **Reconciliation script** (this artifact's output gates everything else). ← starting here
2. Hand-fix ambiguities → commit placement map into the Timeline component dir.
3. Rewrite `Timeline.js` as the CSS-grid component; join GQL labels by slug.
4. Rewrite `Timeline.css` (grid + cards + modal); delete the vendored Leaflet styles.
5. Remove the `leaflet` dependency once nothing imports it.
6. (Later) migrate placements into the GraphQL schema; retire `x/y/w/h/z/o`.
